## 프로젝트 개요

**Score Filter** 는 설문 응답 파일을 업로드하면 척도별 점수, 통계 요약, 해석 구간, 고위험군을 자동으로 분석해주는 데이터 필터링 시스템입니다.

엑셀이나 CSV로 수집된 응답 데이터를 매번 수작업으로 정리하지 않고, 미리 설정한 척도 문항과 점수 기준에 맞춰 빠르게 분석하는 것이 목표입니다. 특히 상담이나 후속 조치가 필요한 고위험군을 별도로 분류하고, 상담 연계 동의 여부까지 함께 확인할 수 있도록 만들었습니다.

개인 프로젝트로 개발했으며, 약 4일간(2026.04.30 ~ 2026.05.03) 구현했습니다.

## 개발 배경

설문 기반 점수 데이터는 현장에서 자주 엑셀 파일 형태로 관리됩니다. 하지만 실제 분석 과정은 생각보다 반복 작업이 많습니다.

- 문항별 응답값을 점수로 변환해야 하는 작업
- 척도별 총점을 계산하고 해석 기준을 적용하는 작업
- 고위험군만 따로 추려내는 작업
- 연락처, 나이, 상담 연계 동의 여부를 함께 확인하는 작업
- 분석 기준이 바뀔 때마다 엑셀 수식을 다시 수정해야 하는 문제

파일을 받을 때마다 같은 과정을 반복하면 시간이 많이 들고, 수식이나 필터 조건이 조금만 잘못되어도 결과를 신뢰하기 어렵습니다.

Score Filter는 이 흐름을 웹 애플리케이션 안으로 가져와, **업로드 → 점수 계산 → 통계 확인 → 고위험군 추출 → 엑셀 다운로드**까지 이어지는 분석 과정을 하나의 화면에서 처리하기 위해 만들었습니다.

## 핵심 기능

### Excel/CSV 업로드

사용자는 `.xlsx`, `.xls`, `.csv` 파일을 업로드할 수 있습니다. 첫 번째 시트를 기준으로 데이터를 읽고, 첫 행의 컬럼명을 기준으로 통계 분석과 척도 문항 매칭을 수행합니다.

업로드된 파일 원본은 저장하지 않고, 파싱된 행 데이터와 컬럼 메타데이터만 DB에 저장합니다. 사용자별로 최근 10개 업로드만 유지해 데이터가 불필요하게 쌓이지 않도록 했습니다.

### 컬럼 자동 통계 분석

업로드된 컬럼은 값의 형태를 기준으로 자동 분류됩니다.

- 수치형
- 범주형
- 전화번호
- 출생년도/생년월일
- 학번

각 타입에 맞춰 평균, 중앙값, 분포, 고유값, 연도별 집계 등을 계산합니다. 문항 설정에서 특정 컬럼 타입을 강제로 지정할 수도 있어 자동 감지가 애매한 데이터도 보정할 수 있습니다.

### 척도지 설정

관리 화면에서는 필터 그룹, 척도, 문항, 점수 옵션, 해석 구간을 직접 설정할 수 있습니다.

문항은 업로드 파일의 컬럼명에 포함될 키워드로 매칭됩니다. 예를 들어 특정 문항 키워드가 업로드 컬럼명에 포함되어 있으면 해당 컬럼을 척도 문항으로 인식합니다.

점수 옵션은 응답 레이블과 점수값을 함께 저장합니다. `1. 전혀 없음`처럼 숫자 prefix가 붙은 응답도 처리할 수 있고, 설정한 레이블과 응답 텍스트를 정규화해 매칭합니다.

### 척도별 점수 계산과 해석

업로드된 응답값은 문항별 점수 옵션에 따라 점수로 변환됩니다. 이후 척도별 총점을 계산하고, 설정된 해석 구간에 따라 결과를 분류합니다.

해석 구간에는 성별 조건을 적용할 수 있습니다. 같은 점수라도 남성/여성 기준이 다른 경우를 고려해 `전체`, `남`, `여` 조건을 나누어 설정할 수 있게 했습니다.

### 고위험군 필터링

해석 구간 중 고위험군으로 지정한 범위에 해당하는 응답자는 대시보드의 고위험군 표에 표시됩니다.

고위험군 표에서는 이름, 성별, 나이, 연락처, 해당 척도, 점수, 해석 수준을 함께 보여줍니다. 또한 상담 연계 동의 문항 키워드를 설정하면, 업로드 데이터에서 동의 컬럼을 찾아 동의 여부도 함께 표시합니다.

### Excel 다운로드

분석 결과는 고위험군과 일반군으로 나누어 Excel 파일로 다운로드할 수 있습니다.

다운로드 파일에는 원본 응답 데이터뿐 아니라 척도별 점수, 해석 결과, 고위험 여부, 상담 연계 동의 여부가 포함됩니다. 현장에서 후속 상담이나 별도 보고 자료를 만들 때 바로 활용할 수 있도록 구성했습니다.

### 회원가입과 관리자 승인

사용자는 회원가입을 신청하고, 관리자가 승인한 뒤 서비스를 사용할 수 있습니다.

관리자 화면에서는 가입 신청 승인/거절, 사용자 활성화/비활성화, 비밀번호 재설정, 사용자별 업로드 파일 확인이 가능합니다. 업로드 데이터와 척도 설정은 사용자 단위로 격리되도록 구성했습니다.

## 기술 스택 및 선택 이유

| 기술 | 선택 이유 |
|------|-----------|
| Next.js 16 App Router | 화면과 API Route를 하나의 프로젝트에서 관리하기 위해 선택 |
| TypeScript | 대시보드와 설정 화면의 복잡한 상태를 타입 안전하게 처리 |
| Tailwind CSS 4 | 테이블, 패널, 설정 폼 중심의 관리형 UI를 빠르게 구성 |
| `xlsx` | Excel/CSV 파싱과 분석 결과 Excel 다운로드 구현 |
| `@libsql/client` | 로컬 SQLite와 Turso 원격 DB를 같은 코드로 다루기 위해 사용 |
| `jose` | JWT 기반 세션 쿠키 검증 |
| `bcryptjs` | 사용자 비밀번호 해시 저장 |
| Vercel | Next.js 애플리케이션 배포와 운영 환경 관리를 위해 사용 |

## 아키텍처

Score Filter는 Next.js 단일 애플리케이션 구조로 구성했습니다.

- **App Pages** — 로그인, 회원가입, 대시보드, 설정, 관리자 화면
- **API Routes** — 업로드, 통계 계산, 척도 점수 계산, 고위험군 조회, Excel 다운로드, 인증/사용자 관리
- **Database Layer** — `@libsql/client` 기반 SQLite/Turso 연결과 초기 스키마 생성
- **Domain Logic** — 점수 응답 정규화, 문항 매칭, 해석 구간 적용, 고위험군 분류

로컬에서는 `file:data/database.db`를 사용하고, 운영 환경에서는 `TURSO_DATABASE_URL`과 `TURSO_AUTH_TOKEN`을 통해 Turso DB로 전환할 수 있습니다.

현재 배포는 Vercel을 기준으로 진행했습니다. Oracle Cloud 서버 구성이 가능해지면 직접 운영하는 방식으로 전환할 예정이라, 지금은 로컬 파일 DB 대신 Turso를 연결해 서버리스 환경에서도 데이터가 유지되도록 구성했습니다.

## 기술 선택 과정

### Oracle Cloud 준비 전까지 Vercel을 선택한 이유

처음에는 Oracle Cloud Always Free 서버에 직접 배포하는 방식을 고려했습니다. 특히 Ampere A1 Flex는 무료 범위 안에서도 비교적 넉넉한 CPU와 RAM을 사용할 수 있어, 작은 개인 프로젝트를 올리기에는 매력적인 선택지였습니다.

다만 실제로는 인스턴스 생성 단계에서 시간이 걸렸습니다. 원하는 A1 Flex 리소스를 바로 생성하기 어려웠고, 용량 부족으로 인해 여러 번 다시 시도해야 하는 상황이 반복됐습니다. Oracle Cloud 서버를 만들 수 있다면 그쪽으로 다시 옮길 계획이지만, 그 전까지 프로젝트를 공개해둘 임시 배포 환경이 필요했습니다.

그 과정에서 무료 플랜 조합을 찾아보다가 Vercel + Turso 구성을 선택했습니다. Score Filter는 Next.js 기반 애플리케이션이고, 별도의 상시 실행 백그라운드 작업이나 복잡한 서버 프로세스가 필요한 구조가 아니었습니다. Vercel을 사용하면 GitHub 연동, 자동 배포, 환경변수 관리, Next.js 최적화된 빌드 환경을 바로 사용할 수 있어 임시 배포 환경을 빠르게 마련할 수 있었습니다.

결과적으로 현재 단계에서는 직접 서버를 운영하는 방식보다, 무료 플랜 안에서 빠르게 배포 가능한 관리형 조합을 사용하는 쪽이 현실적이었습니다.

### Supabase와 Turso 사이의 고민

데이터베이스는 Supabase와 Turso를 두고 고민했습니다.

Supabase는 PostgreSQL 기반이고 Auth, Storage, Realtime 같은 기능까지 제공하는 완성도 높은 BaaS입니다. 만약 이 프로젝트가 파일 스토리지, 실시간 기능, 소셜 로그인, Row Level Security 기반의 복잡한 권한 모델까지 필요했다면 Supabase가 더 적합한 선택이었을 것입니다.

하지만 Score Filter에서 필요한 DB 역할은 비교적 명확했습니다.

- 사용자 계정과 승인 상태 저장
- 업로드된 엑셀 행 데이터를 JSON 형태로 저장
- 척도, 문항, 점수 옵션, 해석 구간 저장
- 고위험군 계산에 필요한 관계형 조회

즉, 대규모 백엔드 플랫폼보다는 가볍고 단순한 SQL 저장소가 더 잘 맞았습니다.

무료 플랜 기준으로도 선택 기준이 갈렸습니다. Supabase는 무료 플랜에서 Postgres와 여러 백엔드 기능을 함께 제공하지만, DB 용량 제한과 비활성 프로젝트 pause 정책을 고려해야 합니다. 반면 Turso는 SQLite/libSQL 계열이라 프로젝트 구조가 단순하고, Vercel 같은 서버리스 환경에서 HTTP 기반으로 연결하기 편했습니다.

로컬 개발에서는 `file:data/database.db`를 사용하고, 운영에서는 같은 `@libsql/client` 코드로 Turso에 연결할 수 있다는 점도 장점이었습니다. 로컬과 배포 환경의 DB 접근 방식을 크게 바꾸지 않아도 되었기 때문입니다.

결론적으로 현재 임시 배포 단계에서는 Supabase의 다양한 기능보다 **가벼운 SQL 저장소, Vercel 배포와의 궁합, 로컬 SQLite와 운영 Turso 사이의 전환 용이성**이 더 중요했습니다. 그래서 Turso를 선택했습니다.

## 구현하면서 신경 쓴 점

### 반복 작업을 줄이는 설정 구조

분석 기준이 코드에 직접 작성되면 실제 사용자가 척도나 문항을 자유롭게 변경하지 못하고, 변경이 필요할 때마다 개발자가 하나씩 수정해야 합니다. 이런 문제가 발생하지 않도록 척도, 문항, 점수 옵션, 해석 구간을 모두 화면에서 관리할 수 있게 만들었습니다.

기본 척도는 초기 데이터로 제공하되, 사용자가 복제하거나 수정해서 실제 현장 데이터에 맞출 수 있도록 설계했습니다.

### 업로드 데이터의 소유권 분리

설문 데이터는 민감할 수 있기 때문에 사용자별 격리를 기본 조건으로 두었습니다. 업로드 파일은 `uploaded_by`, 척도 설정은 `created_by`를 기준으로 조회와 수정 범위를 제한합니다.

### 고위험군 확인 흐름

단순히 점수만 계산하는 도구가 아니라, 후속 조치가 필요한 대상을 빠르게 찾는 것이 핵심이었습니다. 그래서 고위험군 표에는 점수뿐 아니라 나이, 연락처, 상담 연계 동의 여부를 함께 배치했습니다.

분석 결과를 확인한 뒤 바로 고위험군/일반군 Excel 파일로 내려받을 수 있게 해, 웹 화면에서 끝나지 않고 실제 업무 흐름으로 이어지도록 했습니다.
